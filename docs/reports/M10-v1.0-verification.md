**v1.0.0 发布候选通过本机生产构建验收。** 从五行名单选出第 2、4 行后，实际下载的 ZIP、合并 PDF 封面与正文、双格式审计和 SHA-256 清单均与原始行号相符。真实 Edge 在两个视口通过 90/90 个场景，完整保留前九个里程碑的 76 个场景。五路由的文字、可操作控件与焦点测量都达到本轮阈值。生产域名严格校验通过，尚未部署。

## 两行子集，从浏览器下载到逐页核验

EN 与 AR 各在两个视口上传同一份两页 AcroForm 和五行 UTF-8 CSV。第 5 行因姓名过长被标记。所有行都使用相同文件名模式 `packet.pdf`，先依次勾选原始第 4 行和第 2 行，然后筛出含第 2、4、5 行的搜索结果。清空后，界面显示双语提示且五个下载入口均禁用。点击“选择匹配的就绪行”后，仅第 2、4 行入选，清除搜索条件后仍显示所选两行。[浏览器下载与交互](../../tests/e2e/m10-subset.spec.ts)

| 原始名单行 | 下载的 ZIP 成员 | 在可编辑成员读回的 ID | 合并 PDF 的索引页码 |
|---|---|---|---|
| 2 | `packet-2.pdf` | `00222` | 2–3 |
| 4 | `packet-4.pdf` | `00444` | 4–5 |

可编辑成员读回阿语姓名及未映射的 `KEEP 00109`。CSV 和 JSON 审计逐项相同，两种格式都保留 `rowNumber`、`filename`、`status`、`diagnostics`、`fontSizes`。Node 独立解压每份下载，按成员的实际 PDF 字节对照清单中的名称、长度和 SHA-256，再对照整份合并文件的哈希。首次下载清单记录原始来源、`exportScope: "selected-subset"` 和 `selectedRowNumbers: [2, 4]`。生成 ZIP 和合并件后，清单分别追加对应摘要。显式恢复全部就绪行后，清单列出 `[1, 2, 3, 4]`，旧子集的成品摘要已清除。[旧清单与替换名单回归](../../tests/e2e/m9-custody-margin.spec.ts)

PyMuPDF 从下载封面的矢量文字标记和渲染字形两个位置分别读回索引，逐字测量可见墨迹。每个样本含 34 个索引字形，四次共 136 个。正文每页与对应 ZIP 成员按 4× RGB 逐像素比较，四次共 16 页。Node 共复核 8 个 ZIP 成员及 4 个合并文件的 SHA-256。[下载 PDF 独立核验](../../tests/e2e/m10-subset-proof.py)

## 键盘、颜色与焦点

五条正式路径为 `/`、`/arabic-pdf-form-filler`、`/ar/pdf-mail-merge`、`/preserve-leading-zeros-pdf` 和 `/privacy-and-proof`。每次冷启动使用新的浏览器上下文。各路由检查空载页面和快捷键窗口，两种语言的已上传、已预览、已导出工作台另作检查，共 24 个页面状态。[路由测试](../../tests/e2e/m10-keyboard.spec.ts)

键盘实测覆盖真实 `?`、阿语 `؟`、按钮打开、Tab 和 Shift+Tab 首尾循环、Escape 关闭并回到原控件。在本页关闭单字符快捷键后，`?` 和 `/` 均停止响应。启用时 `/` 从按钮移入队列搜索，在搜索框内可正常输入这两个字符。方向键在筛选后的原始行之间移动，并同时核实焦点和当前记录。对话框按 W3C 的焦点循环与恢复示例测试，单字符开关按 WCAG 2.1.4 检查。[W3C 对话框模式](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) · [W3C 字符快捷键](https://www.w3.org/WAI/WCAG22/Understanding/character-key-shortcuts.html)

文字取实际 CSS 前景、各层背景与透明度。边界取相邻颜色和有效填充。浏览器原生复选框、单选框与滑杆取 Edge 实际绘制的像素。键盘模式下逐一聚焦并测量轮廓，同步从 Edge 可访问树读取可操作角色的名称、地标及 polite 状态。手机展开的两个来源指纹各占一张独立卡片，每个 64 位十六进制摘要逐字符用 DOM Range 测得两行，各 32 字符。[测量方法](../../tests/e2e/m10-accessibility.ts) · [W3C 文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) · [W3C 非文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)

|---|---:|---:|---:|
| 可见文字及输入值 | 1,886 | 5.6467∶1 | 4.5∶1 |
| 可操作控件的边界、填色或可见识别标记 | 578 | 3.2056∶1 | 3∶1 |
| 焦点轮廓与相邻背景 | 604 | 5.8819∶1 | 3∶1 |

按未舍入值判定。累计检查 890 个应有名称的可访问树节点，名称缺失 0。各非弹窗状态均有 polite 状态通知，重复区域名称 0。十个冷启动各只请求一个入口 JS，空载 PDF 引擎、嵌入字体及处理模块请求 0。阿语排版通过本地 CSS 字体显示。

旧版三个输入边界的实际对比度为 1.4589∶1，修正后为 3.9535∶1。快速关闭再打开帮助时，旧主线 80 次漏开 62 次，同步关闭修复后相同操作 80/80 次成功。正式回归在每个路由与视口上均保留连续三轮 Escape → `?`，中间不等待组件卸载。常规关闭亦分别核对按键触发位置和按钮本身。[经验记录](../../LESSONS.md#用连续的真实按键验证原生对话框2026-11-27)
