## 实际下载的来源与成品

每个视口在英文入口上传有 BOM 和 CRLF 的真实 CSV，在阿语入口上传 XLSX。两者使用同一份合成 PDF。Node 从上传缓冲区或原始文件直接计算 SHA-256，再解压浏览器下载的 ZIP，逐个读取 PDF，核对文件名、精确字节数和 SHA-256。合并件同样按完整下载字节核算。英文包有两份可编辑 PDF，阿语包有四份，另有一行长姓名在预检中被标记并跳过。可编辑成员同时读回各自的 ID 和未映射字段 `KEEP 00109`。[下载用例](../../tests/e2e/m9-custody-margin.spec.ts)

| 对象或操作 | 下载核对 |
|---|---|
| 原始模板 | SHA-256 为 `f42fce29a41d5e6a1ecf0c4100362a194d21e0664ee562e505f51fe04ea3479d`。 |
| 原始名单 | CSV 为 `70dfc33e7129b9c2fdc979f28555d607d6a83ec2c5fd4f5caa6ca6a656ab058e`，XLSX 为 `05d71504ae1138fdbe99174cbec98b75e956f976b5120f684611269e8877d50b`。 |
| 仅完成预检 | 清单只含版本 1、模板和名单指纹。下载旧版审计 JSON 和 CSV 后仍只含这三个字段。两种审计格式均逐字段核对了 `rowNumber`、`filename`、`status`、`diagnostics`、`fontSizes`。 |
| 先 ZIP，后合并 PDF | 第一次清单只有 ZIP 成员指纹。第二次清单同时保留全部成员及合并件指纹。切换压平后，两个成员均移除 AcroForm，两个摘要均随实际文件字节变化。 |
| 修改输出或来源 | 切换封面／页脚／压平、更改文件名模式、内联修改 ID、以同名文件替换名单和模板后，旧成品摘要消失。修改名单单元格保留原始文件摘要，替换同名源文件则改为新文件摘要。 |

两张带指纹的 EN/AR 核心封面均有可见墨迹。真实 Edge 下载另在英文双视口分别生成无封面、无页脚封面和带页脚封面三个版本。带页脚版本中，53 个非空白字符逐字形核对文字、位置和墨迹。每个字形范围内有 16–196 个深色像素，同一位置在关闭页脚的版本中为白色。三个版本的四页正文在 4× 灰度渲染下逐页相同。[下载页脚校验](../../tests/e2e/m9-cover-proof.py)

## 纸边与预览

QA 制作了两页非零偏移 CropBox 的合成 PDF。控件 `Name` 在第一页距左边 3.25 pt，在顺时针旋转 90° 的第二页距可见右边 7.5 pt。四个浏览器场景中只显示这两条警告。已映射、恰好距边 9 pt 的 `ID`，以及距边 1 pt 的未映射控件未列入。所有合格行仍可导出。100% 缩放时，跳页前后导引线四边距均为 11.984375 CSS px，和理论值 12 px 相差一个浏览器子像素单位。[合成模板](../../tests/e2e/m9-margin-fixture.ts)

Lead 用另一份实体 PDF 与 PyMuPDF 交叉检查了 0°、90°、180°、270°、MediaBox 回退、直接与间接 `/UserUnit`。间接单位读取修正前后的反例及十进制临界点收录于经验记录。[M9 经验](../../LESSONS.md#用实际页面单位和十进制坐标核对-9-pt-临界点2026-11-27)

## 复跑和经验晋升

第一次受限运行时，两项已有发布单测在固定的 D 盘缓存目录创建临时文件夹时遇到 `EPERM`。像素命令在 tsx 读取账户信息时遇到 `uv_os_get_passwd ENOMEM`。两者均保留首轮日志，在获准的本机环境以相同主线、D 盘输入和原命令复跑，分别得到 83/83 和完整像素收据。Vite 对延迟加载的大块给出体积提示，首屏入口字节数由发布检查和冷启动实测单独核定。

复查 M1–M9 后，预览服务退出和 Windows 像素入口恢复这两条达到晋升门槛的经验都已写入代码标准。后者本轮复现一次，累计四个周期。纸边换算新增一个周期。此次没有新增达到三个独立周期的规则。[代码标准](../code-standards.md) · [经验记录](../../LESSONS.md)
