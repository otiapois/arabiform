## 从队列到实际下载

- **先预览，再应用和撤销。** 先加载 Workshop 工作流，再上传三行测试名单。只选 Name 列，把 Alef 归一化，将空白压缩，并按字面把句点换为感叹号。应用前显示受影响 2 格、2 行，两条样本的前后文本与源字符串逐字符相符。预览前后，首行编辑框和 ZIP 中的源姓名仍含原有首尾空格及连续空格。应用后三行姓名为 `احمد سالم!`、`ايمان!`、`ليلى`。撤销后解包验证三份 PDF 的 Name 和 ID，原始姓名、标点、空格及 `00123`、`00007`、`00891` 全部恢复。[桌面清洗预览](screenshots/m7/desktop-m7-hygiene-and-align.png) · [移动端编辑器](screenshots/m7/mobile-m7-editor.png)
- **用墨迹验证居中。** Workshop 中将首行姓名改成“ليلى حسن”，对 Name 选择 Center。桌面和移动端均从实际 PDF.js 画布的 Name 控件内部读取深色像素。以 125% 预览，居中时两侧各约 368.33 个画布像素。下载 `00123.pdf` 后用 PyMuPDF 4× 将文字外观与去除该文字的同页比较，读出 1,372 个墨迹像素，左右边距各 883 个渲染像素，字段原文及前导零编号正确。核心测试另外对四种对齐模式各测五个旋转或重复控件，Center 的五对边距分别为 242/242、50/50、90/90、24/24、62/62。明确的 LTR 和 RTL 分别紧靠左、右内边距 6 px。切换瞬间的 LTR 取样曾读到 410 个暗像素。桌面另行等待界面显示“Generated row”再连续取三帧，各模式的三次读数各自一致。稳态 LTR 为 103 个暗像素，左右边距 5.33/732.33。RTL 为 732.33/4.33，Auto 为 731.33/6.33，Center 为 368.33/368.33 个画布像素。原始读数保存在 `qa-live-stable-ink.json`。[画布和文件回读](../../tests/e2e/m7-evidence.ts) · [核心布局样本](../../scripts/verify-pdf-pixels.ts)
- **预设互通。** 实际导出的 v4 JSON 含 `alignOverrides.Name = "center"`。依次导入 v1、v2、v3，均恢复 Auto，并核对各版本的文件名、字号、压平 ZIP 和封面开关。重新导入刚下载的 v4，恢复 Center、原文件名、8 pt 和两个关闭的开关。[预设测试](../../tests/e2e/m7-power-editor.spec.ts)

## 双向文字与空载页面

在桌面与移动的阿语来源卡中，`.xlsx` 单独处于 `<bdi dir="ltr">` 内。点和单词位于同一行，点的左坐标严格小于单词左坐标，按视觉顺序计算的位置倒置量为 0 CSS px。旧版使用 LRM 时，同机点的左侧也已在单词左侧。两段 Range 的边缘有 0.015625 CSS px 的亚像素交叠。新版同机仍可测得该边缘交叠。此项变更给扩展名加上了显式方向隔离。[阿语来源卡](screenshots/m7/desktop-m7-ar-rtl-fixed.png)

| 阿语来源卡视口 | 点的左坐标（CSS px） | 单词的左坐标（CSS px） |
|---|---:|---:|
| 1440 × 900 | 1210.828125 | 1213.750000 |
| 390 × 844 | 264.671875 | 267.593750 |

另一项可见问题出现在英文清洗示例。旧构建把目标字形排到箭头左边、三个 Alef 源字形排到其右边。Taa Marbuta 和 Alef Maqsura 也有同样问题。两种视口的字符坐标断言复现了错误。提交 `0557c33` 为示例及两端文字设方向隔离后，三个选项均通过同一行、源在箭头左、目标在右的复测。已按修复后界面重拍并打开两张清洗图。本次四张截图均来自真实 Edge 视口。[复测与坐标断言](../../tests/e2e/m7-power-editor.spec.ts) · [经验记录](../../LESSONS.md)

两种视口分别从 `/`、`/arabic-pdf-form-filler`、`/ar/pdf-mail-merge` 等待页面空闲。六次访问均未请求 PDF 引擎、嵌入字体 JS 或样本 JS。页面排版所用的本地 CSS 字体已计入原始同源请求。M7 场景还核对本地及会话存储、IndexedDB、Cache Storage、Service Worker 注册和 cookies 均为空。移动端采用 390 × 844 触屏模拟，桌面为 1440 × 900。范围限于本机浏览器和实际套件覆盖的模板、字体及控件。实体打印、移动真机和线上部署未验证。
