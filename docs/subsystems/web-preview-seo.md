- On the same routes, **Create template** loads the bilingual starter studio on demand. [Starter contract](pdf-engine.md#bilingual-starter-templates)
- **Verify receipt** loads on demand on the same routes. Accept a batch manifest and delivered PDFs or pasted structured QR text. Show the computed and recorded SHA-256 values for PDF comparisons where available, and the row number and digest prefix for QR record results. Label each result in the active locale. The result describes agreement with the unsigned manifest supplied for that check. [Verifier contract](pdf-engine.md#offline-receipt-verification)

Placing another radio while one is selected adds a widget to the same group. Numeric position and size use PDF user space. A focused field can be nudged with arrow keys in 1 pt steps, or 5 pt with Shift, relative to the displayed page. Field changes support delete and Undo.
  - **Save Field Layout (.json)** downloads the current field layout. **Load Field Layout (.json)** restores it only against a flat source with the matching SHA-256. **Download AcroForm Template (.pdf)** saves the reusable PDF. **Use in Fill PDFs Now** passes the generated bytes through normal Fill intake, keeping the current roster available for mapping and ordinary row preflight. ## Local Batch Drafts

- **Save Draft (.json)** downloads a local v1 file with effective cell edits, applied hygiene summaries, and mapping and output settings. It embeds v13 for active data validation rules, otherwise v12 for 4-up settings, v11 for active conditional rules, v10 for an active text formatting override or approval seal, v9 for an active grouping column, v8 for 2-up, v7 for QR or a different cover language, v6 when virtual columns are in use, v5 with an active watermark, or v4. Each settings version loads under the same source matching rules. A draft may contain roster cell values. Source PDF, roster, and font bytes are supplied locally when restoring. The draft is persisted in the downloaded file only, with no cloud storage or `localStorage`.
- **Load Draft (.json)** validates the JSON before applying settings. The active PDF and roster must match the stored SHA-256 fingerprints and the expected fields, exact worksheet name, ordered columns, and row count. The XLSX fingerprint covers the original workbook bytes. If the draft used a custom font, the selected font bytes must also match the stored SHA-256 fingerprint. A mismatch reports a local error before applying draft changes.
- Export row selection is a workbench control outside the saved settings.
