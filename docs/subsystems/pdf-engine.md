- `src/core/template/diff-migrator.ts` inspects both PDFs with the AcroForm intake guards. A signed, encrypted, XFA, flat or unreadable source blocks comparison. Each successful comparison records the SHA-256 of each original PDF's exact bytes. Equal field structures can have different byte fingerprints.
- Compare canonical names and field kinds, widget sizes, text `/MaxLen`, and dropdown or radio export options. Pair repeated widgets by 1-based page and order on that page. Unresolved PDF field references block the migrated preset.

## Batch PDF comparison and delta reprints

- `src/core/diff/batch-diff.ts` compares two complete local archives. It accepts classic single-disk ZIPs with stored or deflated entries, with up to 2,000 entries, 64 MiB of archive bytes, 128 MiB of expanded data and 32 MiB per member. The expansion guard caps a member's expanded size at the larger of 1 MiB and 250 times its compressed size, subject to the member and archive limits. A safe empty directory entry is allowed. Reject unsafe or duplicate paths, non-PDF files, bad ZIP metadata or CRCs, and unreadable, encrypted, XFA or signed PDFs before returning a result. Flattened PDFs are eligible.
- Match safe slash-delimited relative paths after Unicode NFC normalization, with case-sensitive matching across archives. Reject equivalent path aliases within each archive. For a matched path, a matching SHA-256 means `unchanged` and a different SHA-256 means `modified`. An unmatched new or previous path is `added` or `removed`, respectively. A renamed or moved PDF is an addition and a removal even if its bytes are identical.
- Compare supported AcroForm `/V` values on modified pairs, including text, checkboxes, radio buttons, dropdowns and list boxes. Keep the exact decoded text and array values, including Arabic diacritics and leading zeros. A missing value is represented as `null` and an explicit empty string stays empty. The report uses `visual-or-flattened-change` when bytes differ and no comparable value difference is found. This reason also covers metadata and appearance-stream changes and does not establish a visual difference.
- `delta-reprint-pdfs.zip` contains only modified and added files, with relative subfolders and the exact PDF bytes from the new archive. A comparison with nothing to reprint produces an empty ZIP. `batch-diff-audit.csv` uses RFC 4180 quoting and formula-neutralized cells. The versioned `batch-diff-audit.json` preserves the original values. Both record SHA-256 hashes over the complete previous, new and delta ZIP byte streams. The audits are unsigned and may contain personal data.
- `delta-reprint-summary.pdf` is a one-page Arabic and English summary with the four classification counts. Estimated savings equal the new batch page count minus the delta page count, divided by the new batch page count. The estimate assumes one PDF page per sheet and is unavailable when the new batch has zero pages. It excludes the separate summary page. ## Custody Manifest

`src/core/audit/custody.ts` calculates SHA-256 locally. The receipt uses `version: 1`, `templateSha256`, and `rosterSha256`. Workbench receipts add `exportScope` (`'all-ready'` or `'selected-subset'`) and `selectedRowNumbers`, the original 1-based positions of the passing rows in scope, in roster order. The source hashes cover the exact bytes of the original PDF and original CSV or XLSX file, including the full workbook for XLSX. With the worksheet opened by default, the existing v1 fields apply and the workbook hash plus the first-visible rule identify the worksheet. After an explicit tab switch, add `sheetName` with the exact active worksheet name even if the operator returns to the first visible tab. CSV uses the existing v1 fields.

A successful ZIP export adds `entries`, with `filename`, `sha256`, and `bytes` for each final PDF member. Each digest covers the final member bytes, including any flattening, watermark, and QR stamp. A successful merged export adds `mergedPdfSha256`, computed over the complete saved PDF, including any cover, watermarks, and QR stamps. Both sets of hashes can be present for the same batch and settings. The standalone JSON receipt has its own schema, leaving the CSV and JSON preflight audit formats intact. Recipients can compare file bytes using the full digests and a trusted copy of the unsigned receipt.

For a grouped individual ZIP, each standalone receipt entry also carries the exact `zipPath`. The split ZIP includes its own unsigned `batch-custody.json` at the archive root. It records the source hashes and optional worksheet name, version, export scope, selected original row numbers, and `groupByColumn`. Its `groups` entries record the raw `groupValue` (null for blanks), safe `folder`, `zipPath`, `rowNumbers`, `filename`, `sha256`, and `bytes`. Each digest covers the final grouped PDF, including any cover and print options. The row numbers in the receipt correspond to the exported records' original 1-based roster positions.

Optionally record `qrRecords` as `{ rowNumber, payload }` entries in the v1 receipt after a successful print export in custody QR mode. Only rows actually stamped in the exported scope qualify. Combined merged PDFs, split merged PDFs, and flattened ZIP members can carry these records. Editable ZIP members and custom QR patterns leave the QR record ledger untouched. Each structured payload is `ARABIFORM:1:<12 lowercase hex digits>:<original 1-based row number>`. Compute the prefix from the first 12 lowercase hex digits of the SHA-256 of the UTF-8 JSON array `["ArabiForm custody QR v1", templateSha256, rosterSha256, sheetName ?? null]`. Cell values are outside this payload.

## Offline Receipt Verification

`src/core/custody/verify.ts` reads local unsigned v1 batch manifests. Earlier receipts with output hashes still provide byte comparisons. A source-only receipt supplies no evidence of an exported file. PDF verification hashes the submitted bytes and looks for the full digest among relevant `entries`, `mergedPdfSha256`, and split `groups`. An exact grouped path identifies one member. The standard merged file is `arabiform-merged.pdf`. A bare filename can have multiple candidate digests when groups share that name. A renamed file with an unrecognized name can match an issued output by digest.

| Verdict | Meaning relative to the supplied receipt |
| --- | --- |
| `VERIFIED_EXACT_MATCH` | The submitted PDF's complete SHA-256 matches a recorded output digest. |
| `TAMPERED_BYTE_MISMATCH` | The name or path identifies a recorded PDF, and none of its candidate digests match the submitted bytes. |
| `VERIFIED_QR_RECORD` | The structured QR text and original row match a record in `qrRecords` for this receipt's source digest prefix. |
| `UNMATCHED_UNKNOWN` | The receipt identifies no applicable matching PDF output or QR record. |

QR verification covers record membership only. Use the PDF input for a byte comparison. The receipt is unsigned, so both results rely on the supplied manifest. Issuer authenticity requires separate evidence.

## Bulk Filled PDF Extraction

- `src/core/extractor/` processes 1–200 named PDF byte arrays locally. It computes SHA-256 on the original bytes of each input. Apply the encryption, XFA and signature intake guards before reading field dictionaries. Each file yields a row in input order, with text, checkboxes, dropdowns, list boxes, and radio groups read from the saved interactive form.
- Report `extracted` or `warning-schema-mismatch` for readable forms. The first readable form supplies the reference field names and types. Compare later files for missing or additional names and field type changes, and order the union by first appearance. Blocked files keep their filename and hash with empty field cells and a status of `blocked-flat`, `blocked-encrypted`, `blocked-xfa`, `blocked-signed`, or `blocked-invalid`.
- Retain the exact decoded text, including Arabic combining marks, bidirectional punctuation, and IDs such as `00123`. Give each checkbox a `checked` or `unchecked` cell and its native value in a separate cell. Report the saved export value for dropdowns and radio groups, plus the label when it differs.
