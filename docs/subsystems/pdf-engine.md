# Subsystem: PDF & Font Shaping Engine (`src/core/pdf/`)

## Responsibilities
- Pure browser- and Node-compatible TypeScript module (`src/core/pdf/`) with zero external network calls.
- Reference proven baseline algorithm from `D:\workspace\vibe_coding\sites\import-medic\docs\research\M1.5\02-evidence\acroform-baseline.cjs` and evolve it to production quality:
  1. **Strict PDF Intake Gate**:
     - Inspect raw AcroForm dictionary BEFORE `getForm()`.
     - Reject `/XFA` (`xfa-unsupported`), encryption (`encrypted-pdf`), and signature fields (`signed-pdf-warning`) before accessing the form. `flat-scanned-no-fields` means the PDF has no supported editable text, checkbox, dropdown or radio group.
     - Field metadata exposes the canonical name, kind, editability, existing value, and every widget's rectangle, page and rotation. Text metadata also includes `maxLength`, multiline and default appearance font size. Supported dropdowns and radio groups expose their choice labels and export values as exact Unicode strings.
     - `widget-overlays.ts` projects the visible portion of a widget rectangle into the displayed page box, taking `/CropBox`, `/MediaBox`, and page `/Rotate` (0°, 90°, 180°, 270°) into account. The overlay carries `pageNumber` and `widgetIndex` starting at 1, the canonical `fieldName`, and `rect: [x, y, width, height]`. Coordinates and dimensions are normalized from the upper-left corner of the displayed page, so the same metadata can position hit targets at each preview zoom level. Each visible occurrence of a repeated field keeps its own bounds.
     - `inspectTemplateCapacities` can reuse intake metadata or open the template itself, without roster data. It reports each recognized field and its widgets with 1-based page and widget numbers, widget `/MK /R` rotation, and usable dimensions in points after rotation, border and padding. A field without widgets still appears in the report. `/MaxLen` is reported separately from the size estimates.
     - Eligible text estimates use the export shaper and fit rules, including multiline wrapping, at the active minimum size with the bundled Noto faces. The engine repeats representative vocalized Arabic (`مُحَمَّد سَالِم `) or Latin (`Marwan Salem `) strings and counts Unicode code points, including combining marks and spaces. `/MaxLen` bounds the estimate when set, and exceptionally large boxes use a 2,048-code-point sample ceiling. Widgets that cannot provide a text estimate have empty values. A supported widget with insufficient space can report zero. Row-level preflight checks actual roster text across all mapped widgets.
     - `margin-preflight.ts` checks all mapped widget rectangles against the visible page box. It uses the intersection of `/CropBox` and `/MediaBox` when it has positive area, and otherwise uses `/MediaBox`. It accounts for `/UserUnit` and page rotations of 0°, 90°, 180°, and 270°. A signed nearest-edge clearance below 9 pt yields a `margin-near-edge` advisory with the canonical field name, 1-based page number, displayed edge, and clearance in points. A widget past the edge has negative clearance. This template geometry check leaves row readiness and export eligibility unchanged.
  2. **Bundled Local Fonts (`public/fonts/`)**:
     - Bundle OFL-licensed `Noto Naskh Arabic` (Regular) + `Noto Sans` (Regular) locally so both pure Arabic (with harakat/diacritics), pure Latin/numeric IDs (`00123`), AND mixed Arabic+Latin/digits work 100% offline with zero external requests!
     - A local custom font can be passed as `PreflightOptions.customFont` (maximum 16 MiB). `inspectCustomFont` validates its SFNT structure and reports the internal family name. Supported outlines are TrueType and OpenType CFF v1. Multi-dictionary CID-keyed CFF fonts and CFF2 are unsupported. Corrupt or unsupported fonts return `invalid-custom-font`. Mapped text and dropdown labels use only the selected custom face and flag missing coverage as `missing-glyphs`. The worker reuses the parsed face and embeds the shaped glyphs in each output.
  3. **True Ink-BBox Shaping & Auto-Baseline**:
     - Shape Arabic runs via `@pdf-lib/fontkit` after ordering mixed text with `bidi-js`. Keep numeric IDs with `#` and international phone groups with `+` left-to-right using layout-only isolates. Preserve Arabic-Indic digits, paired brackets, and the exact logical source in `/V`.
     - Flag authored directional overrides and isolates and unsafe or unsupported joining controls. Preserve a contextual Arabic ZWJ or ZWNJ when the bundled font can shape it. Flag malformed Unicode, unsupported control characters, and missing glyphs before writing a PDF.
     - Calculate true ink bounding box (`yMin`, `yMax`, total advance width) across all glyphs including descenders (`ن`, `ى`, `ي`, `م`, `ق`) and diacritics.
     - Auto-fit font size within `[options.minFontSize (default 8pt, user adjustable 6–10pt), templateFontSize || 12pt]` against inner box (`width - 2*pad - 2*border`, `height - 2*pad - 2*border`).
     - Vertically center true ink (`yMin..yMax`) inside the widget rect to guarantee **zero top/bottom clipping**.
     - Each mapped text field may set `alignOverride` (`auto`, `rtl`, `ltr`, or `center`). `auto` uses the default direction-based anchor. `rtl` anchors the ink at the right edge and `ltr` at the left edge of the inner box. `center` centers the shaped ink width inside that box. Horizontal placement follows the override while mixed-script ordering, exact logical `/V` values, and ink-fit checks continue to use the shaping engine.
     - Support single-line AND multiline wrapping (when field has multiline flag, wrap by word boundaries and check total line height against inner height; flag overflow if it exceeds box height!).
     - Multi-widget atomicity: if a canonical field appears on multiple pages/widgets, verify ALL widgets fit; if any widget fails, flag the field fail-closed!
     - Checkbox mapping trims whitespace and accepts case-insensitive `true/false`, `yes/no`, `1/0`, `x`/blank, and `نعم/لا`. Any other cell value yields `invalid-checkbox-value`. A mapped checkbox reuses the original on and off appearance streams across all widgets. Missing or inconsistent states yield `unsupported-checkbox-appearance` before any PDF is written.
     - Choice mapping tries an exact match against the dropdown or radio group's labels and export values first, then a match after trimming surrounding whitespace. Each step requires a single matching choice. Matching preserves case and Unicode code points. Unknown or ambiguous values yield `invalid-choice` with the legal `{value, label}` alternatives.
     - Dropdowns write the selected export value and render the display label with shaped fonts and widget ink-fit checks. Radio groups resolve supported export values to widget appearance states and reuse the original on/off streams. Malformed choices or unusable appearances fail closed. Multi-select lists and free-form values outside the listed choices are outside the mapping contract.
  4. **Row-Level Batch Execution & Outputs**:
     - For each roster row, return deterministic `RowPreflightResult` with `status: 'pass' | 'flagged'`, per-field diagnostics with every failed widget index where applicable, computed font sizes, and rendered bytes when a caller requests a PDF for a passing row. Diagnostic and row `pageNumbers` are sorted, deduplicated, and 1-based. Widget failures reference the failing widget's page.
     - Resolve virtual text mappings against the original parsed roster position and the captured local date before the ordinary text field preflight. The resolved string, including any prefix, suffix, or leading zeros, is the value checked for `/MaxLen` and ink fit and written to `/V` when it passes. [Virtual column and filename contract](roster-mapper.md#responsibilities)
     - A size-limited widget includes `requiredFontSizePt` when the actual ink placement fits at a smaller floor of at least 6 pt. The value is an already tested size on the 0.01 pt grid. Apply the minimum of all suggestions only when every row diagnostic contains one. `/MaxLen` flags include `maxLengthExcess` counted in Unicode code points. Comb fields remain unsupported even when their values meet `/MaxLen`.
     - The browser uses `src/core/worker/client.ts` to run preflight and both exports in one dedicated, locally bundled module worker per batch. Preflight measures rows in groups of 25 and retains the template, fonts, row inputs, and diagnostics. The worker produces PDFs for the selected preview and for export on demand. During export, each generated source PDF is consumed before advancing to another row. This bounds intermediate ready-PDF work while the ZIP bytes or merged PDF still accumulate in memory. Final output size, page count and template complexity affect memory use. Progress carries phase and completed/total row counts. Disposing the worker immediately cancels CPU work and rejects pending requests with `AbortError`.
     - Both PDF export commands accept `rowSelection: 'all-ready' | readonly number[]` and default to `'all-ready'`. Explicit arrays contain original 1-based parsed roster positions. Resolve them against the latest preflight results to distinct passing rows in roster order. Exports with zero passing rows in scope fail with `empty-export`. Both modes reuse the full batch filename plan so collision suffixes stay stable in subsets.
     - Support **two PDF export formats**:
       1. **Individual PDFs in `.zip`** (`fflate` MIT) with a sanitized filename pattern such as `{{ID}}-{{Name}}.pdf` and collision suffixes such as `-2` and `-3`. The worker ZIP command defaults `flattenZip` to `false`. When `true`, it flattens each ready record with the same active-appearance path as merged PDF export.
       2. **Merged single printable PDF** combines the flattened pages of the ready records in scope in row order.
          - `imposition` defaults to `1-up`. Select `2-up` for a single-page template to place consecutive ready records on A4 sheets. For a multi-page template the merge uses `1-up`. The ZIP export uses its own editable or flattened path.
          - Compare portrait and landscape A4 sheets with stacked and side-by-side slots to maximize the uniform scale for both records. Maintain an 18 pt outer margin and gutter. The source's visible crop and displayed rotation carry into its slot. Draw 0.35 pt cut marks outside the record boundary. The odd final row uses the first slot at the same scale and leaves the second slot blank. Watermarks and vector QR stamps are drawn on the record before imposition and scale with it.
          - If embedding a record would remove a visible non-widget annotation marked for printing, 2-up stops with a message to use 1-up.
          - An optional **Batch Print Manifest** precedes the filled pages. Its `coverLanguage` is `auto` (the page locale), `en`, `ar`, or `bilingual`. Bilingual mode places English and Arabic headings and summary statistics side by side on the first page, using one shared index. Continuation pages retain the paired title. The worker records the date at export and displays the local calendar date as `YYYY-MM-DD`. The template filename and locale come from the export request. The minimum size and active font mode come from the prepared preflight state.
          - **Ready** counts printed rows, **Flagged** counts flagged rows across the full preflight, and **Skipped** counts the total roster rows minus those printed. Each index entry shows the printed sequence number, the row's original 1-based position in the batch, and the final filename. In 1-up, its range starts at `coverPages + precedingFormPages + 1` and ends at `start + rowPages - 1`. In 2-up, its range is the single physical sheet number `coverPages + ceil(sequenceNumber / 2)`, so adjacent records on one sheet share that number, including when the cover has continuation pages.
          - Shape cover text with the bundled Noto fonts, including Arabic and Latin filenames even when the form rows use a custom font. Wrap names and paginate the index. If cover text cannot be rendered or fit, fail the covered export and let the user retry the standard merge with the cover off. Pixel verification compares the cover ink against page margins and the filled pages against their individual exports at 4×.
          - An optional footer on each cover page prints the first 12 hexadecimal characters of the original template and roster hashes under the labels `Template SHA-256` and `Roster SHA-256`. The full source hashes remain available in the custody manifest.
     - **Optional print watermark** — The print path can stamp record pages in merged PDF and flattened ZIP with `DRAFT`, `CONFIDENTIAL`, `مسودة`, `سري`, or a single line of custom text up to 32 Unicode code points. It shapes the text with the bundled Noto fonts and fails export if they lack a required glyph. The supported angles are −45°, 0°, and 45° in the page's displayed orientation, with opacity from 0.08 through 0.30. New stamps start at 45° and 0.14 opacity. Fit uses the glyph ink bounds with the page's visible box and rotation. The cover is outside the stamp scope.
     - **Optional print QR stamp** — `qr-stamp.ts` generates a local QR Code in Byte mode with versions 1–6 and error correction M, using Reed–Solomon error correction and mask scoring. The capacity is 106 ASCII bytes, or 105 UTF-8 bytes with ECI assignment 26 for non-ASCII text. The encoder uses pure TypeScript and no QR dependency. [Roster pattern contract](roster-mapper.md#qr-payload-patterns)
       - The four displayed corner anchors place a black vector matrix on a white 36–72 pt square, including the four-module quiet zone. Pick geometry in physical points using the visible page box, page rotation, and the 9 pt safe margin. Reject insufficient space or any overlap between the full white square and a visible form widget.
       - Use the same record payload for each page in that record. Stamp only the record pages of merged PDFs and flattened ZIP members. A disabled placement is `none`. Invalid payloads or placement errors stop the requested stamped output before download. Check finder patterns, the complete module grid, quiet zone, and inset in the 4× raster verification.
     - **Untouched Field Invariance** — Individual editable PDFs preserve raw `/V`, `/AS`, and `/AP` for unmapped widgets and fields. Flattened exports paint the active widget appearances into the page and remove interactive form widgets. They fail if a visible widget is missing the required appearance. The 4× pixel comparison covers the fixture exports, and testing a new PDF reader or printer still requires opening a sample there.
     - **Audit Report** — Export deterministic `.json` and `.csv` preflight audit logs with original row number, filename, status, field font sizes, and flag reasons. In `'all-ready'` mode the audit includes every row, including flagged rows. In `'selected-subset'` mode it includes only the selected passing rows, and an empty subset fails with `empty-export`. Both formats keep the existing diagnostic shape. Choice flags include the legal values and labels. Diagnostic page numbers are available to preview navigation. CSV escapes formula-like cell prefixes, including Unicode compatibility forms and prefixes after leading whitespace or formatting controls. JSON retains exact strings.

## Custody Manifest

`src/core/audit/custody.ts` calculates SHA-256 locally. The receipt uses `version: 1`, `templateSha256`, and `rosterSha256`. Workbench receipts add `exportScope` (`'all-ready'` or `'selected-subset'`) and `selectedRowNumbers`, the original 1-based positions of the passing rows in scope, in roster order. The source hashes cover the exact bytes of the original PDF and original CSV or XLSX file, including the full workbook for XLSX. XLSX receipts include `sheetName` with the exact selected worksheet name. CSV receipts omit `sheetName`.

A successful ZIP export adds `entries`, with `filename`, `sha256`, and `bytes` for each final PDF member. Each digest covers the final member bytes, including any flattening, watermark, and QR stamp. A successful merged export adds `mergedPdfSha256`, computed over the complete saved PDF, including any cover, watermarks, and QR stamps. Both sets of hashes can be present for the same batch and settings. The standalone JSON receipt has its own schema, leaving the CSV and JSON preflight audit formats intact. Recipients can compare file bytes using the full digests and a trusted copy of the unsigned receipt.
